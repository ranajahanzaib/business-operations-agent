# Tool contracts

| Tool                             | Inputs                                                                           | Permission | Purpose                                                                         |
| -------------------------------- | -------------------------------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------- |
| `list_delayed_orders`            | strict overdue days, reference timestamp, bounded limit                          | Read       | Find open orders with promise timestamp strictly before `as_of - overdue_days`. |
| `list_support_tickets`           | bounded customer/order/category/status filters                                   | Read       | Inspect ticket records and duplicates.                                          |
| `get_support_ticket`             | ticket ID                                                                        | Read       | Inspect one ticket and its current version.                                     |
| `get_order`                      | order ID                                                                         | Read       | Inspect order status and line items.                                            |
| `list_customer_orders`           | customer ID and bounded limit                                                    | Read       | Inspect a customer's order history.                                             |
| `check_inventory`                | SKU                                                                              | Read       | Inspect availability and reservation quantities.                                |
| `propose_delayed_order_tickets`  | overdue days, reference timestamp                                                | Proposal   | Stage tickets for uncovered qualifying orders.                                  |
| `propose_inventory_reservation`  | eligible order ID                                                                | Proposal   | Stage reservations for every order line, subject to stock checks.               |
| `propose_ticket_priority_update` | ticket ID, target priority, reason                                               | Proposal   | Stage a priority change for an eligible ticket.                                 |
| `propose_support_ticket`         | customer ID, optional order ID, category, priority, subject, description, reason | Proposal   | Stage one support ticket for approval.                                          |

The server validates and bounds model arguments; queries are fixed SQL and never generated by the model. Each tool event records bounded arguments, start/end times, outcome, and result. The export at `/api/tools` is the current machine-readable schema surface. Model tools can only read data or prepare a proposal. The operator approval endpoint executes the immutable, hashed proposal through guarded transactional code; no direct model write tool exists.

For ToolFault-style experiments, `/api/runs/{run_id}/trace` returns the used tool definitions and ordered, bounded invocation/response records with timestamps and a scenario identifier. Email and credential-like fields are redacted. `opsagent.testing.ToolResponseReplay` is test-only and can be injected into tests; normal API clients cannot choose replacement tool responses.
